# TIL 등록 워크플로우

사용자가 이미 작성한 TIL 본문(markdown)을 채팅에 붙여넣으면, 이 저장소의 관례에 맞는 위치에 파일로 만들고 인덱스에 등록한다.
목표: 사용자는 본문만 쓰면 되고, 카테고리 판단 / 파일 생성 / 인덱스 갱신은 이 스킬이 처리한다.
**본문을 대신 작성하거나 지어내지 않는다** — 사용자가 준 내용을 그대로(또는 포맷만 다듬어서) 사용한다. 본문이 아직 없다면 먼저 본문을 붙여넣어 달라고 요청한다.

## 0. 이 저장소의 구조 파악

TIL 콘텐츠 영역은 두 곳이다. `docs/Study`, `docs/Project`는 책 스터디/프로젝트 기록이라 TIL 대상이 아니므로 건드리지 않는다.

| 영역 | 글 디렉터리 | 인덱스 파일 |
|---|---|---|
| Tech (일반 기술) | `docs/Tech/~/<category>/` | `docs/Tech/tech_index.md` |
| Go | `docs/go/~/<category>/` | `docs/go/go_index.md` |

각 인덱스 파일은 `### 카테고리명` 헤더 아래에 `- [제목](~/category/filename.md) - 설명` 형식의 링크 목록이다.

**주의**: 카테고리 디렉터리명과 인덱스의 헤더 텍스트가 항상 일치하지 않는다 (예: 디렉터리 `ps` → 헤더 `### Data structure`). 헤더를 새로 지어내지 말고, 반드시 해당 카테고리 디렉터리로 가는 기존 링크를 grep해서 실제 쓰이는 헤더를 찾아라. 새 카테고리를 만들 때만 새 헤더를 짓는다.

## 1. 카테고리 결정

1. 사용자 설명의 주제를 보고 `docs/Tech/~/*`와 `docs/go/~/*` 중 어느 영역인지, 그리고 어떤 카테고리(하위 디렉터리)에 해당하는지 판단한다.
2. 기존 카테고리와 명확히 일치하면 그대로 사용한다 (예: k8s/컨테이너 얘기 → Tech `container`).
3. 애매하면 짧게 사용자에게 물어본다 (예: "network 카테고리로 넣을까요, 아니면 security로 넣을까요?"). 완전히 새로운 주제라 새 카테고리가 필요해 보이면, 새 카테고리를 만들지 확인부터 받는다.

## 2. 파일명 결정

- 기존 파일명 스타일을 따른다: 소문자 kebab-case, 영문 (예: `syn-flooding.md`, `go-defer.md`).
- 카테고리 디렉터리 안의 기존 파일 목록을 먼저 확인해 이름이 겹치지 않는지, 네이밍 톤이 비슷한지 확인한다.

## 3. 본문 확인

- 사용자가 본문을 아직 주지 않았다면, 먼저 markdown 본문을 붙여넣어 달라고 요청하고 기다린다.
- 사용자가 준 본문은 그대로 사용한다. 오타/포맷(제목 레벨, 코드블록 등)만 저장소 관례에 맞게 다듬는 정도만 허용하고, 내용을 추가하거나 창작하지 않는다.
- frontmatter는 쓰지 않는다 (기존 포스트들은 `# 제목`으로 바로 시작).

## 4. 파일 생성

`docs/<Area>/~/<category>/<filename>.md`에 Write로 파일을 만든다. 카테고리 디렉터리가 없으면 새로 생성한다.

## 5. 인덱스 갱신

1. 해당 인덱스 파일(`tech_index.md` 또는 `go_index.md`)을 읽는다.
2. 카테고리로 가는 기존 링크를 grep해서 실제 헤더 텍스트를 찾는다 (`~/<category>/`로 검색).
3. 그 헤더 섹션의 맨 위(헤더 바로 다음, 첫 링크 위)에 새 줄을 추가한다: `- [제목](~/category/filename.md) - 한 줄 설명`
   - 제목은 파일의 H1과 일치시킨다.
   - 설명은 8~20자 내외로 핵심만 (기존 항목들의 톤 참고).
4. 카테고리가 새로 생기는 경우, 인덱스 최상단(첫 `###` 헤더 위)에 `### 카테고리명\n- [...]\n\n`을 추가한다. 헤더 이름은 디렉터리명을 그대로 쓰지 말고 사람이 읽기 좋은 제목으로 짓는다 (예: `ps` → `Data structure`처럼 기존 관례 참고).

## 6. 완료 보고

무엇을 어디에 만들었는지, 인덱스에 어떤 줄이 추가됐는지 요약한다. **git add/commit은 사용자가 명시적으로 요청하기 전까지 하지 않는다** — README TOC는 pre-commit 훅(`scripts/update_toc.py`)이 커밋 시점에 알아서 갱신하므로 이 스킬에서 따로 손댈 필요 없다.
